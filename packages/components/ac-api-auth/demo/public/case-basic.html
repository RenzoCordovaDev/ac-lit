Simula login, registro, logout, validación y refresco de token.

Propiedades

  • version String, por defecto 'v1'

    Versión de los mocks / del servicio simulado que se consume. No cambia el comportamiento por sí sola — es informativa, para simular múltiples versiones de API en una demo o integración.

  • timeout Number, por defecto 3000

    Milisegundos de latencia simulada antes de resolver o rechazar cada llamada. Se aplica por instancia: todas las llamadas de esa instancia esperan el mismo tiempo configurado.

  • simulateError Boolean, por defecto false

    Si es true, fuerza que toda llamada posterior falle (dispara el evento de error correspondiente) sin tocar los datos mock — pensado para probar el manejo de errores del consumidor. Se puede alternar en caliente.

Métodos públicos

  • iniciarSesion(email, password)

    Valida email/clave contra el mock y devuelve { token, usuario }.

    Dispara: ac-api-auth-login-success / ac-api-auth-login-error
  • registrarCuenta(objetoCuenta)

    Crea una cuenta (nombre/email/clave obligatorios, email único) y la deja autenticada — mismo resultado que iniciarSesion.

    Dispara: ac-api-auth-register-success / ac-api-auth-register-error
  • cerrarSesion(token)

    Invalida el token; falla si la sesión no existe o ya expiró.

    Dispara: ac-api-auth-logout-success / ac-api-auth-logout-error
  • validarSesion(token)

    Comprueba que el token siga activo y devuelve el usuario asociado.

    Dispara: ac-api-auth-validate-success / ac-api-auth-validate-error
  • refrescarToken(token)

    Invalida el token anterior y entrega uno nuevo para el mismo usuario.

    Dispara: ac-api-auth-refresh-success / ac-api-auth-refresh-error

Eventos

ac-api-auth-login-success, ac-api-auth-login-error, ac-api-auth-register-success, ac-api-auth-register-error, ac-api-auth-logout-success, ac-api-auth-logout-error, ac-api-auth-validate-success, ac-api-auth-validate-error, ac-api-auth-refresh-success, ac-api-auth-refresh-error
